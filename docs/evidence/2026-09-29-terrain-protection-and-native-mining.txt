真机反馈五：被 C 型槽困住、误伤建筑与平整地形、镐子是帧操
==========================================================

原话：

> 会被某些地形困住（C型槽），会在很多情况下破坏玩家建筑物或者玩家的平整地形，
> 使用镐子是类似于之前跳跃一样的帧操导致效率低下。可能还有别的问题。

三件事分别查，代码里的根因都不一样。


一、镐子是帧操：`Player.PickTile` 每一帧直接调用
------------------------------------------------

旧实现：

    public void DigTile(int x, int y)
    {
        reflection.PlayerPickTile.Invoke(player, new object[] { x, y, PickPower, 1 });
    }

`Player.PickTile` 是原版**一次挥镐结算**的那个函数，由 `ItemCheck` 在使用镐子时
调用。它在一次调用里就把镐力算成挖掘伤害并打上去，还带一次命中音效/粒子。
每帧调一次 = 每帧挥一镐，于是：

- 完全不看镐子的 `useTime` 与 `itemAnimation`，也就是玩家说的"帧操"——
  画面里角色没有挥镐动作，石头却在掉；
- 挖掘速度与镐子的真实速度无关，计划里"镐子分担 23 格（约 0.4 分钟）"这类
  估算就只是纸面数字；
- 与跳跃那次是同一类错误：**绕过原版的状态机，直接改结果**。

改法与跳跃一致——走原版通道，让游戏自己挥：

    public void DigTile(int x, int y)
    {
        int slot = FindPickaxeSlot();      // Item.pick 最大的那一格
        if (slot >= 0 && slot != currentSlot) SelectSlot(slot);
        AimAt(x, y);                        // 鼠标指到目标格
        SetInput(reflection.InputMouseLeft, true);   // 按下使用键
        mining = true;
    }

执行器在够得着的每一 tick 继续请求，直到目标格不再是实心；换目标或放弃时
调 `StopDigging()` 松开。`SetMovement` 里那句"没用就松开使用键"因此要多看一个
`mining` 标志：挖矿是持续按住，扔雷管是只按一帧，两者不能混。

顺带修掉一个顺序坑：墓碑分支原来是先 `SetMovement(0,0,false)` 再 `DigTile`，
`SetMovement` 会把使用键清掉。现在统一"先挥镐、再站位"。


二、误伤建筑与平整地形：三处来源，分开堵
----------------------------------------

**(1) 走路时挖出的沟** —— 这是"平整地形被破坏"的主因。旧走位把 A* 路线上的实心
路点一律挖掉，于是从地表走到站位就可能横穿玩家的田地。

现在分两层门槛（`CanRouteDig`）：

- 头顶必须有 **3 格实心岩层**（`Covered`）才允许挖：地下隧道从地表看不出来，
  而地表那一层挖掉就是一道疤；
- 任何**自建墙**后面（`TileWall != 0`，运行时读 `Terraria.Tile.wall`，
  按规划器同一套"非世界生成墙"规则）一律不挖。

两层都过不去就不挖，改由看门狗决定是脱困还是放弃（见第三节）。

**(2) 雷管炸到玩家结构** —— 规划器其实一直在保护：`protection=strict` 会给每发
雷管算"爆破范围里有没有家具/容器/自建墙"，写进 zplan 的 hazard 第 32 位。
**但执行器解析 hazard 时只读了 1/2/4/8/16，第 32 位被丢掉了**——计划里标了
"这里会打到结构"，运行时却照炸不误。现在补上：

    charge.HasProtected = (hazards & 32) != 0;

命中就跳过并说明（`StructuresInBlast`），日志点名坐标，留给玩家手动处理。
计划生成之后新盖的房子、新搬来的箱子正是这种情况。可用 `ProtectStructures=false`
关掉。

**(3) 计划自己的挖清单**（封带里雷管炸不动的格子，全图 23 格）—— 这是计划的一
部分，本来就不该被上面两条拦住，保持原样执行。


三、C 型槽困死：加进度看门狗 + 有限脱困
--------------------------------------

旧走位只有"发指令"，没有"没效果怎么办"：卡在槽里就一直重复同一条指令。

现在 `TickGoToStand` 里记录"上一次换格子的 tick"，同一格超过 **90 tick**（1.5 秒）
判定被困，进入脱困：

1. 先挖**身体那一列**（脚、腰、头三格，再算上一格台阶）——只挖脚前那一格是
   第一版的做法，结果玩家站在一个一格的窗口前过不去，照样卡死；
2. 没得挖就**按住跳**（走的是已经修好的按住式跳跃，不是逐帧点）；
3. 每次脱困动作之后**重新给走路一个 90 tick 的窗口**——这一点很关键：
   第一版在卡住时每帧都执行脱困，于是它把自己刚挖通的隧道又继续挖下去，
   明明能走了却一直挖到预算耗尽，最后放弃这一发；
4. 预算用尽（`EscapeDigTiles=6` 格、`EscapeEpisodes=4` 次）或出路必须挖穿
   自建墙，就**放弃这一发**并写清原因（`NoUndamagingRoute`）：
   "到不了站位 (x,y)：被地形困住，而且出路要挖穿墙或你的地面，这一发留给你
   手动处理。"


四、可回归的断言（模拟世界）
----------------------------

`ExecutorTests.RespectsTheWorld` 五条：

- 爆破范围里有玩家结构的那一发不炸（`StructuresInBlast`，0 发）；显式关掉保护后照常施工；
- 只有挖穿自建墙才过得去时：路线挖 0、脱困挖 0、自建墙一格没少、日志写清原因；
- 挖一格要挥好几镐（模拟世界按 `RequiredPickPower` 折算挥镐次数），
  不再是"一帧删掉一格"；
- 被普通岩石关住时自己挖出来把活干完（Finished，1 发），且脱困步数在预算内；
- 地面上的墙不挖、只挖头顶有岩层的路（路线挖 1、脱困挖 0）。

`status.txt` 新增 `escapes=`（脱困挖了几格），和 `walk=` 一起放在同一行。


五、还没解决的（下一轮）
------------------------

- 规划器仍可能在玩家的**平整田地**上排雷管（自然泥土/石块不算"结构"，
  规划器无从区分是天生还是玩家铺的）。要彻底解决得让规划器把"玩家平整过
  的区域"也当保护对象，属于规划侧改动。
- 地下隧道虽然看不见，但长度没有专门收敛；目前只靠 A* 的 `PathDigCost=120`
  把"挖"折算成 12 格走路的代价来间接限制。
- 死亡惩罚（掉钱、墓碑）与液体/坠落规避还未在本轮回归里覆盖。
